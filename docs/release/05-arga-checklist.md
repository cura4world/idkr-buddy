## 1. 업로드 키 만들기 (PC, 5분)

PC 명령창에서 (자바가 깔려 있으면 `keytool` 이 있습니다):

```
keytool -genkeypair -v -keystore kata-store-upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
```

- 비밀번호 두 개(키 저장소·키)를 정하고 **안전한 곳에 적어 둡니다.** 잃어버리면 Play 에 재설정 요청을 해야 합니다.
- `kata-store-upload.jks` 파일은 **저장소에 올리지 마세요.** 관리자판 APK 키와도 다른 키입니다.
- SHA-1 지문을 적어 둡니다 (3번에서 씀):
  ```
  keytool -list -v -keystore kata-store-upload.jks -alias upload
  ```

## 4. Cloudflare — 공개판 서버 `kata-public` (15분)

1. [ ] KV 네임스페이스 `PUBLIC_KV` 만들기
2. [ ] Worker `kata-public` 만들기 → `workers/kata-public/worker.js` 내용을 붙여 넣기 → KV 바인딩 이름 `PUBLIC_KV`
3. [ ] 변수: `GOOGLE_WEB_CLIENT_ID`, `PLAY_PACKAGE`=`app.naruve.katakata`, `PRODUCT_IDS`=`plus`
4. [ ] 비밀값:
   - `AI_PROXY_URL`, `PROXY_SECRET` — **kata-sermon Worker 에 넣은 것과 같은 값** (Cloud Run 중계)
   - `PLAY_SERVICE_ACCOUNT` — 3-5번의 JSON
   - `ADMIN_KEY` — 아무 긴 무작위 문자열 (신고 조회·등급 지정·계정 삭제 대행용, 따로 보관)
   - (평소에는 넣지 않음) `AI_PAUSED` — AI 요청을 급히 멈출 때만 넣는 변수. `free` 면 무료 계정만, `all` 이면 모두 멈춥니다
     (앱에는 평소의 서버 오류 안내가 나옵니다 — 한도는 깎이지 않음). 지우면 바로 풀립니다. 비용이 갑자기 늘 때 쓰는 비상 차단입니다.
   - `ADMIN_KEY` 는 **32자 이상 무작위 값**으로 넣으세요(틀린 시도 횟수를 서버가 세지 않습니다).
4-1. [ ] **(첫 배포 때 권장) 사용량 카운터를 Durable Object 로** — 2026-11-14 추가
   - 무엇: 한도를 세는 곳을 KV 에서 Durable Object(`USAGE_DO`, 클래스 `UsageCounter`)로 옮깁니다. 같은 순간에 여러 번 눌러도 한도가 정확히 지켜지고, 전체 하루 상한도 여기서 셉니다.
   - **무료 요금제에서 됩니다.** Cloudflare 문서 기준 Workers Free 는 "SQLite 방식" Durable Object 만 쓸 수 있고, 이 서버가 그 방식입니다(하루 요청 10만 · 쓰기 10만 행 · 저장 5GB 안. 2026-11-14 확인).
   - **KV 만으로 무료 요금제에서 돌리면 금방 막힙니다.** KV 무료 한도는 **하루 쓰기 1,000번**인데, KV 방식은 AI 호출 한 번에 2~3번을 씁니다(하루 300~400번 호출이면 끝).
     한도에 닿으면 서버는 AI 를 멈추고 "지금은 사용할 수 없습니다"를 냅니다(세지 못한 채 부르지 않게 2026-11-14 에 고침). Durable Object 를 켜면 AI 호출은 KV 를 쓰지 않습니다.
   - **방법: 대시보드에 코드를 붙여 넣는 것으로는 만들어지지 않습니다. PC 에서 한 번 `wrangler` 로 배포해야 합니다.**
     1. `workers/kata-public/wrangler.toml` 에서 `GOOGLE_WEB_CLIENT_ID` 와 KV `id` 두 칸을 채웁니다(이 파일의 `[vars]` 는 대시보드 변수를 덮어씁니다. 비밀값은 덮어쓰지 않습니다). 채운 값은 공개돼도 되는 값이지만, 커밋할지는 정하세요.
     2. 그 폴더에서 `npx wrangler login` → `npx wrangler deploy`. 파일에 Durable Object 바인딩·마이그레이션(`new_sqlite_classes`)·매시간 Cron 이 이미 적혀 있습니다(2026-11-14 `wrangler deploy --dry-run` 으로 설정 확인).
     3. 확인: `curl "https://kata-public.cura4world.workers.dev/admin/budget" -H "x-admin-key: <ADMIN_KEY>"` → `"counter":"durable-object"` 이면 켜진 것. `"kv"` 면 바인딩이 없는 것입니다.
   - 켜지 않고 배포해도 깨지지 않습니다(예전처럼 KV 로 셉니다). KV 로 쓰다가 나중에 켜면 그날의 사용량은 0 부터 다시 셉니다.
   - 알아 둘 것: 무료 요금제의 Worker 는 요청 하나에 CPU 10ms 까지입니다. 로그인(서명 확인)·결제 검증·긴 소리 응답이 이 한도에 걸리는지는 내부 테스트 때 Cloudflare 대시보드의 오류(`exceeded CPU`)로 확인하세요. 걸리면 Workers Paid(월 5달러)가 필요합니다. — 측정하지 못한 항목입니다.
4-2. [ ] **(첫 배포 때 권장) 전체 하루 상한 `AI_DAILY_BUDGET`** — 2026-11-14 추가
   - 무엇: 하루(한국 날짜)에 서버가 AI 쪽으로 보내는 **호출 수**의 천장입니다. 계정별 한도와 별개로, 가입이 몰리거나 누가 계정을 많이 만들어도 하루 비용이 이 선에서 멈춥니다.
     닿으면 그날은 무료·체험·Plus·심사용의 AI 기능이 "지금은 사용할 수 없습니다"로 멈추고(한도는 깎이지 않음), 다음 날 0시(한국)에 풀립니다. Special·관리자는 멈추지 않습니다.
   - 값: 변수(비밀값 아님)로 `5000` 처럼 숫자 하나, 또는 `{"all":5000,"tts":2000}` 처럼 소리만 더 낮게. **비워 두면 상한 없음**(예전과 같음). `AI_PAUSED` 와 함께 쓸 수 있습니다(`AI_PAUSED` 가 먼저).
   - **잘못 적으면 0 으로 보고 모두 막습니다**(상한 없이 도는 것보다 바로 드러나게). 넣은 뒤 위 `…/admin/budget` 으로 `caps` 와 `"invalid":false` 를 확인하세요. 같은 주소로 오늘 나간 호출 수(`used`)도 봅니다(KV 방식에서는 상한을 정한 날만 셉니다).
   - **권장 시작값: `{"all":3000,"tts":1000}`.** 근거 — 무료 한 사람이 하루에 실제로 쓰는 양은 20~30번, Plus 는 100~200번쯤으로 보고, 출시 초기 활성 사용자 50~100명을 넉넉히 덮는 수입니다.
     호출 한 번의 값은 제가 확인하지 못했습니다. 첫 주에 Google Cloud 결제 화면의 하루 비용 ÷ `used.all` 로 한 번 값을 구한 뒤, **"하루에 감당할 금액 ÷ 한 번 값"** 으로 다시 정하세요. 평소 가장 바쁜 날의 3배쯤이 적당합니다.
   - 상한에 닿으면 텔레그램 알림이 하루 한 번 옵니다(4-3 을 설정했을 때). Worker 로그에는 `AI_BUDGET_REACHED`.
4-3. [ ] **(선택) 신고 알림 — 텔레그램** — 2026-11-14 추가
   - 무엇: 새 AI 신고가 저장되면 텔레그램으로 짧게 알립니다(기능·시각·글 앞부분 30자. 계정·이메일은 없음). 한 번 알린 뒤 한 시간 안에 온 신고는 묶어서 한 통으로 보냅니다.
   - 봇 만들기: 텔레그램에서 **@BotFather** → `/newbot` → 이름·아이디를 정하면 **토큰**(`숫자:글자` 꼴)을 줍니다. 만든 봇과의 대화창에서 아무 말이나 한 번 보낸 뒤(봇은 먼저 말을 건 사람에게만 보낼 수 있습니다),
     브라우저로 `https://api.telegram.org/bot<토큰>/getUpdates` 를 열어 `"chat":{"id":…}` 의 숫자를 적습니다(이것이 **대화 ID**).
   - 비밀값 넣기: Worker 의 비밀값(Secret)으로 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. 둘 중 하나라도 없으면 아무것도 보내지 않습니다. 토큰은 저장소·문서·대화에 붙여 넣지 마세요.
   - 묵은 묶음을 매시간 보내는 Cron 은 `wrangler deploy` 로 배포하면 함께 켜집니다(대시보드 배포라면 Worker 설정 → Triggers → Cron 에 `17 * * * *`). Cron 이 없어도 다음 신고가 올 때 함께 알립니다.
   - 알림이 실패해도 신고 저장에는 영향이 없습니다. 전체 목록은 예전처럼 `…/admin/reports`.
   - **켜기 전에 정할 것**: 알림에는 사용자가 신고에 적은 글의 앞부분(30자)이 텔레그램 서버를 거쳐 갑니다. 지금 개인정보처리방침의 처리 위탁·국외 이전 업체 목록에는 텔레그램이 없습니다.
     켜려면 방침(과 `07-data-safety.md`)에 텔레그램을 넣을지 HQ 와 먼저 정하세요. 정하기 전에는 비밀값을 넣지 않으면 됩니다(넣지 않으면 아무것도 나가지 않음).
5. [ ] 주소 확인: `https://kata-public.cura4world.workers.dev/` 를 열면 `{"ok":true,"service":"kata-public"}`
   - 주소가 다르면 `src/lib/account.ts` 의 `PUBLIC_BASE` 한 줄을 고칩니다

- [ ] **(b) 체험 제안 ID 에 `trial` 을 넣기** — 예: `trial-7d`. 서버가 Play 응답에서 체험 단계를 못 읽을 때 이 글자로
      체험을 알아봅니다(`03-architecture.md` "체험 판정"). 이름에 `trial` 이 없으면 체험 중인 사람이 Plus 한도로 잡힐 수 있습니다.

- [ ] **(d) 유예 기간·계정 보류 기간을 정해서 여기에 적어 두기** — 기본 요금제마다 설정합니다.

      → 정한 값: 월간 유예 `___`일 · 보류 `___`일 / 연간 유예 `___`일 · 보류 `___`일

  - **⚠ "주문 및 구독 관리" 권한이 빠지면 구매 조회는 되는데 구매 확인(acknowledge)만 실패합니다.

  - 확인 실패는 Cloudflare 에서 볼 수 있습니다: Worker 로그의 `ACK_FAILED status=403`, KV 의 `ackfail:` 로 시작하는 키(7일 보관).

- [ ] 설정 → 라이선스 테스트 → Arga 님 계정 추가 (실제 결제 없이 구독 시험)

  - [ ] **심사용 Google 계정 만들기**: 심사에만 쓰는 새 Google 계정을 하나 만듭니다(개인 계정을 쓰지 않음). 2단계 인증은 끕니다 — 심사자가 문자 인증을 받을 수 없습니다.
  - [ ] **그 계정에 심사용 등급(review) 주기** (4절의 Worker 가 배포된 뒤 — 2026-11-14 결정: Special 이 아니라 심사용 등급).
        심사용 등급은 **Plus 와 똑같이** 열립니다(한도도 Plus 와 같음). 신앙 메뉴·관리자 화면은 열리지 않고, 결제 없이 쓰며, 기한이 없습니다.
        PC 명령창에서, `<ADMIN_KEY>` 는 4-4 에서 정한 값:
        ```
        curl -X POST https://kata-public.cura4world.workers.dev/admin/special -H "content-type: application/json" -H "x-admin-key: <ADMIN_KEY>" -d "{\"email\":\"심사용계정@gmail.com\",\"action\":\"grant\",\"tier\":\"review\",\"note\":\"play-review\"}"
        ```
        아직 로그인한 적 없는 계정이면 `"pending":true` 로 답하고, 그 계정이 앱에 처음 로그인할 때 등급이 붙습니다(미리 준 등급은 400일 안에 로그인해야 함).
        확인: `curl "https://kata-public.cura4world.workers.dev/admin/special?email=심사용계정@gmail.com" -H "x-admin-key: <ADMIN_KEY>"`
        거두기(심사가 끝난 뒤): 같은 명령에서 `"action":"grant"` 를 `"action":"revoke"` 로.
  - [ ] 내부 테스트 앱에 그 계정으로 로그인해 확인합니다 — ① 홈이 Plus 사용자와 같은 모습(신앙 메뉴 없음) ② 잠겨 있던 기본 단어장·게임 6종·회화집·지도·이해가 열림
        ③ 내 정보의 등급 칸에 "Plus · 심사용 계정", 구독 화면에 "심사용 계정"이 보이고 "구독 관리" 줄은 없음.

## 10. 알고 계셔야 할 것

- **관리자판 APK 빌드(`build-apk.yml`)도 지금은 실패할 가능성이 큽니다.** 스토어 빌드를 만들다 보니
  `android-actions/setup-android@v3` 가 2026-11 러너에서 실패했습니다(마지막 성공은 2026-08-10).
  다음에 관리자판 APK 를 다시 빌드할 일이 생기면 `build-store.yml` 처럼 SDK 설정 단계를 바꿔야 합니다.
- 공개판 사용량 한도는 `workers/kata-public/worker.js` 의 `DEFAULT_LIMITS` 가 정본입니다(무료: 이야기 하루 1 · 새 사전 풀이 하루 50 ·
  오늘의 문장 하루 1 · 긴 읽기와 회화 만들기는 잠김 / Plus: 이야기 하루 5·한 달 60, 회화 만들기 하루 3·한 달 30, 긴 읽기 하루 5·한 달 50 /
  체험: 이 가운데 네 가지가 Plus 의 절반). 운영 중에는 Worker 변수 `LIMITS_JSON` 하나로 바꿉니다.
- **단어 발음**: 스토어 앱에서 인도네시아어 낱말은 폰 내장 음성으로 읽습니다(2026-11 결정, 한도에 세지 않음).
  예문·문장·한국어 듣기는 Gemini 음성이고 한도(`word-audio` 등)에 들어갑니다. 같은 글은 기기에 저장돼 두 번째부터는 세지 않습니다.
- 사용량 한도는 서버가 **부르기 전에 한 칸을 잡고, 실패하면 돌려주는** 방식입니다. Cloudflare KV 는 동시에 쓰는
  값을 원자적으로 맞춰 주지 않아, 한 사람이 같은 순간에 여러 요청을 몰아 보내면 한도를 넘길 수 있습니다.
  **2026-11-14 에 카운터를 Durable Object 로 옮기는 코드를 넣었습니다** — 4절 4-1 대로 켜면 정확히 셉니다. 켜지 않으면 예전(KV) 방식 그대로입니다.
- 공개판 서버는 앱이 실제로 보내는 요청 모양만 통과시킵니다(글·음성 본문과 몇 가지 설정). 나중에 새 AI 기능이
  다른 설정(예: 시스템 지시문)을 쓰게 되면 `workers/kata-public/worker.js` 의 `sanitizeAiBody` 도 같이 고쳐야 합니다.
- Google 로그인 버튼은 지금 글자만 있습니다. Google 의 공식 로그인 버튼 이미지를 넣으려면 Google 브랜딩 안내에서 받은 파일을 쓰세요(제가 로고를 그려 넣지 않았습니다).
