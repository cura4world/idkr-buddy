# 공용 단어장 계획

**41권 3,555단어.** 공개 단어장 01~34번(34권 3,005단어) + 성경과 신앙 35~41번(7권 550단어).
주제별 분류이며 품사는 기준이 아니다. 작업 이력과 원칙은 `DECISIONS.md`, 코딩 규칙은 `CLAUDE.md` 참고.
2026-11 재배치·검토 내역은 `data/REVIEW-2026-11.md`.

## 1. 원칙

- **주제 우선, 품사 무시.** `berdoa`(기도하다)는 동사지만 `39 기도·찬양`으로 간다.
- **빈도 우선.** 채울 때는 인도네시아어 고빈도 어휘부터 넣는다. 희귀어로 칸을 메우지 않는다.
- **표기는 KBBI 표준형.** 생활에서 흔한 비표준형(`nggak`, `udah`, `gimana` …)은 `06 입말·구어`에만 두고 뜻 끝에 `(구어)`·`(은어)`를 붙인다.
  다른 단어장에서는 표준형을 쓴다 (`cokelat`, `lembap`, `kaus`, `mi`, `menyontek`, `siapa pun` …).
- **접사 가족을 활용한다.** 인도네시아어는 어근+접사 구조라 `ajar → belajar / mengajar / pelajaran / pengajar / pelajar`처럼 하나에서 여럿이 나온다.
- **`10 접사 가족`의 역할.** 모든 어근 가족을 모으는 곳이 아니라, 접사 규칙(`me-`, `pe-`, `-an`, `ter-`, `ke-...-an`)이 뜻을 어떻게 바꾸는지 보여주는 **대표 예시 모음**이다. `menulis`는 09, `penulis`는 22에 있어도 된다 — 주제별 분류가 우선이고, 10은 문법 감각을 익히는 보조 단어장이다.
- **공개 단어장끼리 같은 표제어를 두지 않는다.** 단어를 다른 단어장으로 옮기면 옛 자리에서 지운다.
  뜻이 확실히 다른 동음이의어(`tahu` 알다/두부, `bunga` 꽃/이자 …)만 예외로 둔다 (§4).
- **같은 단어장 안에 같은 표제어를 두지 않는다.** 단어 ID가 `shared_{categoryId}_{word}`라 충돌한다. 대소문자만 다른 표제어도 만들지 않는다.
- **예문에는 표제어(또는 그 접사형)가 실제로 들어간다.** 다른 단어장 표제어와 같은 예문을 쓰지 않는다.
- **성경과 신앙(35~41)은 공개판에서 Special Member·관리자에게만 보인다** (`src/lib/wordbookAccess.ts`, `isStaffTier()`).
  관리자판·회원판에서는 지금처럼 모두 보인다.

## 3. CSV 형식 (반드시 지킬 것)

- 헤더 없이 4열: `인니어,한국어,예문,예문뜻`
- BOM 없는 UTF-8, 줄바꿈 LF, 마지막 줄도 개행으로 끝낼 것
- 쉼표나 큰따옴표가 든 필드는 큰따옴표로 감싼다. 필드 안 큰따옴표는 `""`로 이스케이프
  - 예: `lupa,잊다,"Maaf, saya lupa membawa buku itu.","미안해요, 그 책 가져오는 걸 잊었어요."`
- 예문 본문에 큰따옴표를 넣지 않는다. CSV 규격상 필드를 감싸는 따옴표와 혼동되고, 앱 화면에서 그 행만 튄다.
- 예문은 일상적이고 자연스러운 한 문장. 예문뜻은 그 문장의 자연스러운 한국어 번역
- 파일명이 곧 앱에 표시되는 단어장 이름이다. 숫자 두 자리 접두사를 반드시 유지할 것

## 4. 검증

```
node scripts/check-wordlist.js

npx vitest run src/test/sharedIdMigration.test.ts

```

`check-wordlist.js`에서 **중복(뜻이 같음) 0건 / 형식오류 0건 / BOM 0개 / 쉼표 병합 행 0건**이어야 한다.
동음이의어 항목은 의도된 것이라 0건이 아니어도 된다 (2026-11 기준 20건: 공개끼리 11쌍, 공개–성경과 신앙 9쌍).

## 5. 단어장 이름(번호)을 바꿀 때 — 반드시

단어장 ID는 파일 이름에서 나온다 (`shared_` + 빈칸을 `_`로 바꾼 이름). 이름이나 번호를 바꾸면
사용자 기기에 저장된 다시 외울 표시·단어장 순서·접힘 상태가 옛 ID에 묶인 채 길을 잃는다.

1. `src/lib/sharedIdMigration.ts` 에 새 이전 표를 추가하고 **표시 키 버전을 올린다** (`kata-shared-ids-v2` → `v3`).
   이미 돈 이전은 다시 돌지 않으므로, 기존 표를 고치는 것으로는 부족하다.
2. 표기를 고친 표제어는 `LEGACY_WORD_RENAMES` 에 넣는다 (다시 외울 표시가 따라가도록).
3. `src/test/sharedIdMigration.test.ts` 를 새 표에 맞춰 고치고 통과시킨다.
4. `Wordbooks.tsx` 의 `GROUPS` 와 `wordbookAccess.ts` 의 범위를 맞춘다.

### 표제어 표기만 고칠 때 (단어장 이름·번호는 그대로)

단어 ID 에 표제어가 들어 있어(`shared_` + 단어장 ID + `_` + 표제어) 표기를 고쳐도 ID 가 바뀐다.

1. `sharedIdMigration.ts` 의 `HEADWORD_RENAMES_V3`(단어장 ID·옛 표제어·새 표제어)와 `LEGACY_WORD_RENAMES` 에 같은 쌍을 넣는다.
   이미 v3 이전이 돈 기기가 있으면(= 그 빌드가 배포된 뒤라면) 표를 새로 만들고 표시 키를 `v4` 로 올린다.
2. 그림이 있으면 `src/data/illust/*.json` 의 키 이름도 새 표제어로 바꾼다.
3. 고유명사로 대문자를 유지해야 하면 `src/lib/wordCase.ts` 의 `PROPER` 에 넣는다.
4. 오늘의 단어 퍼즐 정답(`src/data/kataHariIniWords.ts`)은 동결 목록이라 **표기가 달라도 고치지 않는다**(뜻 칸만 고칠 수 있음).
5. `src/test/sharedIdMigration.test.ts` 가 "새 글자만 있고 옛 글자는 없는지"를 CSV 와 대조한다.

## 6. 진행 이력

- 0단계 — CSV 파서를 RFC4180 방식으로 교체, `check-wordlist.js` 추가
- 1단계 — 품사별 16권(1,592단어)을 주제별 36권으로 재배치. 중복 31건 제거 → 1,561단어
- 1.5단계 — `baru` ID 충돌 해결, 오타 수정, 이모지 중복 해결, 이 문서 작성
- 2단계 1~6회차 — 36권 3,067단어로 채움 (2026-08-03 완료)
- **3단계 (2026-11-11, S43)** — 41권 체계로 재배치.
  - 번호를 다시 매겨 공개 01~34, 성경과 신앙 35~41. 새 단어장 5권: 01 인사·기본 표현, 06 입말·구어, 21 취미·운동·여가, 26 긴급·안전, 27 사회·경제·뉴스 (496단어, 그중 8단어는 다른 단어장에서 옮겨 옴)
  - 기존 공개 29권 2,517단어를 한 줄씩 검토해 172개 단어(253칸)를 고침 — KBBI 철자, 잘못된 뜻, 비문·사실 오류 예문, 어색한 번역, 중복 예문. 내역은 `data/REVIEW-2026-11.md`
  - 옛 ID → 새 ID 이전을 앱 시작 때 한 번 실행 (`sharedIdMigration.ts`, 표시 키 `kata-shared-ids-v2`)
  - 공개판에서 성경과 신앙은 staff 등급만 보이게 함
- **출시 전 점검 반영 (2026-11-14)** — 검수 보고서의 뜻·철자 지적 148행을 **서로 다른 출처 두 곳 이상**(KBBI, 위키낱말사전, 인니–영 사전. 성경 용어는 TB 표기)으로 다시 확인해
  확실한 47건만 고침(CSV 51행, 표제어 19개 포함). 확인되지 않은 67건은 그대로 두고 목록으로 남김 — `docs/review/content-wordlist-2026-11-14.md`.
  단어 수는 3,555 그대로. 표제어 19개의 ID 이전은 `sharedIdMigration.ts`(표시 키 `kata-shared-ids-v3`).

### 앞으로 단어를 더할 때

1. 이 문서 §2 표의 **목표를 먼저 갱신**한다. 목표 합계와 문서 첫 줄 숫자를 맞춘다.
2. 41개 CSV 전체에서 표제어를 읽어 **제외 목록**을 만들고, 넣으려는 단어와 대조한다.
   같은 뜻이면 넣지 않는다. 뜻이 확실히 다를 때만 동음이의어로 둔다.
3. §3 형식을 그대로 지킨다. 대소문자만 다른 표제어는 앱 목록에서 헷갈리므로 만들지 않는다.
4. §4 검증을 모두 통과시킨 뒤 커밋한다. `src/data/seed.json`은 커밋하지 않는다.
5. 작업이 끝나면 §2 표의 현재값과 §6 이력을 갱신한다.
